# Интеграция с Google Calendar

## Введение
Данная интеграция, как и остальные, создавались для переиспользования готовой инфрастуктуры самих календарей, чтобы сфокусироваться больше над бизнес-логикой самой системы

## Взаимодействие пользователя с Google Calendar API
Так как будут использоваться готовое API от Google, то необходимо поддержать авторизацию через сервисы Google.
В данном случае будет использоваться OAuth Client, который можно настроить через [эту консоль](https://console.cloud.google.com/projectselector2/apis/dashboard?supportedpurview=project).

В остальном будет проводиться проксирование основного API Google Calendar, описание которого можно найти [здесь](https://developers.google.com/workspace/calendar/api/v3/reference).

#### Авторизация по OAuth2
Так как при работе с Google Calendar API нужен будет пользовательский токен, то нужно прихранивать `access` и `refresh` токены.
Этого можно достичь при использовании Spring Boot Security, а также настройки OAuth2-Client (Spring Boot Starter для работы с этим протоколом).
Токены будут храниться в отдельной таблице в рамках нашей БД (PostgreSQL).

Примерная структура для хранения токенов:

| provider | principal_name    | access_token | access_token_expires_at | refresh_token        |
|----------|-------------------|--------------|-------------------------|----------------------|
| gmail    | example@gmail.com | secret_token | 2025-11-05              | secret_refresh_token |

#### Интеграция с endpoints Google Calendar API
[Описание API](https://developers.google.com/workspace/calendar/api/v3/reference)
##### ACL
Данный домен отвечает за права доступа к календарям
+ insert - выдача доступов к календарю по указанному calendarId
+ update - обновление существующего правила к calendarId
+ delete - удаление правила у календаря

----
+ scope.type - тип скоупа, кому выдается доступ
+ scope.value - email пользователя, группа и тд
##### Calendars
Данный домен отвечает за работу с календарями
+ insert - создание календаря
+ delete - удаление вторичного календаря (в рамках проекта подразумевается, что работать будем именно с ним)
+ get - получение информации по календарю
+ patch/update - обновление метаданных календаря

##### Channel
Данный домен отвечает за отправку уведомлений.\
Работа будет происходить с помощью web hook, поэтому наша интеграция должна поддерживать обработку уведомлений от Google Calendar API.

##### Colors
Данный домен отвечает за работу с доступными цветами в Google Calendar - будет использоваться при создании событий.

##### Events
Данный домен отвечает за работу с событиями в календаре.
